             TASK-3: GITHUB ISSUES KANBAN BOARD TRACKER
           REAL-WORLD TESTING EXAMPLES & VERIFICATION GUIDE
========================================================================

This text file provides 5 distinct, real-world repository examples that you can type directly into the search bar, with exact expected outcomes, metadata outputs, and step-by-step verification instructions for each.

------------------------------------------------------------------------
NOTE ON FILTERING UX & DESIGN STANDARDS:
------------------------------------------------------------------------
- Professional Kanban boards (e.g. GitHub Projects, Trello, Jira) maintain their visual columns when filters yield zero matches. 
- The columns do NOT collapse, stack, or disappear; instead, they remain nicely side-by-side in their 3-column grid structure, displaying "0" issue cards. 
- When a new repository is searched, the visual text inputs and dropdown filter selections in the browser UI are automatically cleared to avoid visual-state mismatches.
- KANBAN COLUMNS INITIAL POPULATION RULE:
  * Open: All open issues that have no assignees, 2 or fewer labels, and no progress/review keywords in their labels.
  * In Review: All open issues that are assigned to a developer (meaning work is in progress/active), OR have more than 2 labels (meaning they are actively triaged/categorized), OR contain progress/review/active/wip keywords in their labels. This ensures the "In Review" column is immediately populated with realistic active issues rather than being empty.
  * Closed: All closed issues.

------------------------------------------------------------------------
HOW TO SET UP BEFORE TESTING:
------------------------------------------------------------------------
1. Open the project in your browser through a local web server (e.g., Live Server in VS Code, or python -m http.server).
2. (Recommended) Enter a Personal Access Token (PAT) in the "GitHub PAT" box at the top right to bypass public API rate limits.

EXAMPLE 1: Search "facebook/react" (The Recommended Default)
========================================================================
- Search Input: facebook/react

- Expected Metadata Card Output:
  * Title Link: facebook/react (pointing to https://github.com/facebook/react)
  * Description: "The library for web and native user interfaces."
  * Stars count: Approx 240,000+ (e.g. 245,144)
  * Forks count: Approx 51,000+
  * Open Issues count: Approx 1,300+

- Step-by-Step Functionality Checks:
  1. Observe that Open, In Review, and Closed columns are immediately populated (Closed is no longer empty on Page 1!).
  2. Verify that Open column cards have green accents, In Review has orange, and Closed has purple.
  3. Filter Check: Open the "All Labels" dropdown. Select the label "Component: Developer Tools" or "Component: Fast Refresh". 
     * Expected: Only 1 or 2 issues containing that specific label remain visible. The column count badges (e.g. Open "1", Closed "0") automatically update to reflect the filtered results.
  4. Click "Clear Filters" to return to normal.
